# Технический анализ 3D Home Academy (16.10.2026)

Анализ выполнен без изменения кода. Объём: ~5 400 строк, 44 автотеста.

## 1. Как создана 3D-квартира

С нуля программно, без готовых 3D-моделей.

- Стены, окна, двери, полы, потолки строятся из описания планировки (`data/layouts/type-2k-68.json`): стены с координатами, проёмы, комнаты, точки оборудования. Код сам режет стены вокруг проёмов.
- Мебель и оборудование собраны в коде из скруглённых примитивов — временные модели.
- Текстуры (ламинат, плитка, штукатурка, ткань) генерируются в браузере.
- Загрузка GLB поддерживается библиотеками, но пока не используется.

## 2. Технологии

| Задача | Что используется |
| --- | --- |
| Интерфейс | React 18, TypeScript |
| 3D | Three.js, React Three Fiber, drei |
| Состояние | Zustand, сохранение в localStorage |
| Файлы паспорта | IndexedDB |
| Сборка и тесты | Vite, Vitest |
| Сервер | Node.js без зависимостей |
| Цены | Google Sheets API, сервисный аккаунт |

Объём JS ~1,3 МБ (~370 КБ в сжатом виде).

## 3. Переиспользование 3D-ядра

Частично, ~70 % без переписывания.

**Переносится как есть:** модель планировок и построение стен, зеркалирование и индивидуальные изменения, каталог и чтение Google Таблицы, движок сметы, контракт академий, цифровой паспорт и права, адаптеры интеграций.

**Мешает переносу:**
- 3D-компоненты напрямую читают общее состояние приложения — их нужно отвязать (данные через параметры);
- список типов объектов и набор мебели прописаны в коде (новый тип — правка в трёх местах);
- планировка подключена к сборке, а не загружается по запросу.

Нужна реорганизация в отдельный пакет, а не переписывание.

## 4. Автоматическое создание квартир по планировкам

Да — из подготовленного описания планировки. Нет конвертера из чертежей.

| Источник | Реалистичность |
| --- | --- |
| IFC (BIM) | Высокая |
| DXF/DWG | Высокая при стандартных слоях, нужна настройка под проектировщика |
| PDF (векторный) | Средняя: распознавание + ручная проверка |
| Скан / фото | Низкая автоматизация: нейросеть делает черновик, человек проверяет |

Ограничения геометрии: только прямые стены по осям, прямоугольные комнаты; нет стен под углом, Г-образных комнат, колонн, ниш, двухуровневых квартир, разной высоты потолков; мебель расставлена вручную.

## 5. Новые интерактивные модули

Да. Академия — отдельная папка + строки в таблице; ядро, смета, карточки, сравнение цен, заказы и паспорт не меняются.

- Окна и двери: проёмы уже есть, нужно сделать их выбираемыми объектами и добавить академию.
- Сантехника, электрика, отопление: трассы есть в «Рентгене», но не кликабельны.
- Мебель: нужна библиотека GLB с привязкой к товарам.
- «Ремонт комнаты» — академия-сборщик разделов.

Рекомендация: перенести список типов объектов из кода в данные.

## 6. Google Sheets

Реализовано на сервере: закрытая таблица, сервисный аккаунт, кэш, работа при сбое Google, проверки, раздельные закупочная и продажная цены, фиксация цен в заказах.

Оговорки: проверено на имитации Google, с настоящей таблицей не запускалось. При тысячах товаров, многих поставщиках и редакторах таблица станет узким местом — тогда база данных, а таблица как способ загрузки.

## 7. Основа для сайта «Город мастеров»

Как модуль — да, как весь сайт — нет. 3D-приложение плохо индексируется поисковиками; нужны профили мастеров, CRM, оплата, отзывы, кабинеты. Вариант: сайт отдельный, в него встраивается «Спланировать ремонт в 3D»; каталог и движок сметы — общие для сайта, академии и Naidu.kz.

## 8. Тысячи квартир

| Сейчас | Что нужно |
| --- | --- |
| Сметы, заказы, паспорт в браузере | Сервер и PostgreSQL |
| Роль переключается в интерфейсе | Вход через E-Shanyraq, права на сервере |
| Сумма заказа считается в браузере | Пересчёт и фиксация на сервере |
| Одна планировка в сборке | Планировки в базе, загрузка по запросу, версии |
| Фото в браузере | Хранилище файлов, миниатюры, защищённые ссылки |
| Мебель из примитивов | GLB-библиотека, сжатие, CDN |
| Освещение на лету | Запечённое освещение для типовых планировок |
| Цены в таблице | База с синхронизацией, цены по ЖК и регионам |

Модель данных уже правильная: ЖК → корпус → подъезд → этаж → квартира, геометрия отдельно от квартиры, зеркальные квартиры автоматически.

## Оценка

**Сильные стороны:** разделение данных, расчётов и интерфейса; расчёты — чистые функции с тестами; цены вне кода; модульные академии; честная маркировка демо; интеграции не выдуманы.

**Ограничения:** нет сервера данных и авторизации; прямоугольная геометрия; временные 3D-модели; не тестировалось на реальных телефонах; Google Sheets не проверен с реальным аккаунтом; нет казахского языка; доступность — частично.

**Итог:** годится как основа MVP, переписывать не нужно. Для реальных жильцов не хватает серверной части и защиты данных.

## План масштабирования

1. **Фундамент:** вынести ядро в пакет, типы объектов в данные, сервер с PostgreSQL, вход через E-Shanyraq, данные на сервер, проверка Google Sheets.
2. **Реальные планировки:** формат v2 (многоугольники, стены под углом), конвертер IFC/DXF, редактор проверки, пилот на одном ЖК.
3. **Качество 3D:** GLB с привязкой к товарам, запечённое освещение, сжатие, CDN, тесты на дешёвых телефонах.
4. **Каталог:** база с синхронизацией из Sheets, цены по ЖК и регионам, Naidu.kz и ClimateCool после согласования API.
5. **Новые академии:** окна и двери, электрика и сантехника, мебель, «Ремонт комнаты».
6. **«Город мастеров»:** встраивание, передача заказов мастерам, оплата, фотоотчёты.
