# Архитектура

## Стек

React 18 + TypeScript, Three.js через React Three Fiber и drei, Zustand для состояния, Vite для сборки,
Vitest для тестов, Node.js без зависимостей для сервера. Платных сервисов нет.

## Слои

```
data/                     ← данные, редактируемые без кода
  catalog/*.csv           ← демо-каталог = структура Google Таблицы (6 листов)
  layouts/*.json          ← геометрия типовых планировок (стены, проёмы, помещения, элементы, мебель, коммуникации)
  complexes/*.json        ← ЖК → корпус → подъезд → этаж → квартира (только ссылки на планировку и отличия)
  naidu/offers.csv        ← тестовые предложения для демо-адаптера поиска цен

src/core                  ← доменные типы и контракт академии (не зависит от 3D и UI)
src/catalog               ← CatalogProvider, разбор и проверка листов
src/estimate              ← чистый движок сметы
src/academies/<id>        ← logic.ts (чистые расчёты) + UI (урок и калькулятор)
src/apartment             ← планировки, геометрия стен, 3D-сцена
src/passport              ← цифровой паспорт и права
src/integrations          ← Naidu.kz, «Город мастеров», E-Shanyraq
src/ui                    ← панели и шапка
server/                   ← статика + каталог из Google Sheets
```

## Поток данных

1. `useApp.init()` читает параметры запуска (`?source=eshanyraq&apartment=72`), выбирает квартиру и загружает каталог.
2. Квартира = `resolveLayout(экземпляр)`: типовая планировка → зеркалирование → индивидуальные изменения.
3. Нажатие на объект → `AcademyDefinition` по `element.academy` → раздел сметы (`<квартира>|<академия>:<помещение>`).
4. Раздел хранит уровень (эконом/комфорт/премиум), выбор по позициям и параметры калькулятора.
5. Академия превращает раздел в `EstimateSection` (позиции + базы для норм) → `computeEstimate()` по данным каталога.
6. Заказ копирует строки сметы (цены фиксируются). Выполненный заказ создаёт записи в паспорте.

## Выбор объектов

Все выбираемые объекты описаны одной моделью (`src/apartment/objects.ts`): категория, значок, помещение, точка метки, академия.
Новый тип объекта = строка в `KIND_META` и элемент планировки с полем `academy`.

* **Касание ≠ вращение.** Объект или пол выбираются, только если палец сдвинулся меньше 6 px; любое перетаскивание — это вращение камеры.
* **Пол** выбирает комнату и больше ничего не открывает.
* **Метки** с названиями показываются только для выбранной комнаты (или для категории, выбранной в списке «Объекты») — без визуального шума на общем виде.
* **Выбор объекта** подсвечивает его и показывает плашку снизу: «Как устроено» и «Цена и варианты». Панель академии открывается только по кнопке.
* **Список «Объекты»** группирует всё по помещениям с фильтром по категориям — работает при любом количестве объектов.
* Составные части (наружный блок) помечены `partOf` и выбираются как основной объект.

## Как добавить академию (например, «Окна»)

1. В Google Таблицу: товары со `slot` вида `window.profile`, `window.glass`; работы; комплектации для `econom/comfort/premium`; нормы расходников.
2. `src/academies/windows/logic.ts` — расчёт позиций из геометрии (проёмы уже есть в планировке).
3. `src/academies/windows/WindowsUI.tsx` — урок и калькулятор.
4. Зарегистрировать объект `AcademyDefinition` в `src/academies/index.ts` и указать `elementKinds`.
5. В планировке указать у элементов `"academy": "windows"`.

Ядро, смета, карточки, сравнение, заказы и паспорт не меняются.

## Как добавить ЖК или квартиру

* Новая типовая планировка — файл в `data/layouts` и регистрация в `src/apartment/layout.ts`.
* Квартира — строка в `data/complexes/*.json`: `layoutId`, `mirrored`, `overrides` (скрыть/добавить элемент, переименовать помещение).
* Геометрия не дублируется: 200 квартир одного типа ссылаются на одну планировку.
* Следующий шаг — импорт чертежей (DXF/IFC → JSON планировки) отдельным конвертером; сложная BIM-система не требуется.

## Режим жильца и мастера

`proMode` в контексте академии: уроки и карточки показывают нормативные подробности и все характеристики.
Роль влияет на права: закупочная цена — только администратору; статусы заказов — мастеру/администратору;
чеки в паспорте не видны мастеру.

## Производительность и мобильные устройства

* Отдельные чанки `three` и `r3f`, процедурные текстуры без загрузки файлов.
* На телефоне: тени 1024 px, `dpr ≤ 1.5`, панели как нижний лист, крупные зоны нажатия у мелких объектов.
* Стены со стороны камеры автоматически срезаются до ~1 м («кукольный домик»).
