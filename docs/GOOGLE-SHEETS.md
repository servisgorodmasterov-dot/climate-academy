# Цены и каталог в Google Таблице

Все товары, цены, расценки работ, комплектации, поставщики и нормы расхода хранятся вне кода.
Меняете таблицу — меняется смета. Код трогать не нужно.

## Быстрый способ — таблица по ссылке, без сервера

Подходит для демо и GitHub Pages. Закупочные цены в этом режиме не читаются (таблица открыта по ссылке).

1. Откройте `docs/templates/3d-home-academy-catalog-template.xlsx` в Google Диске → «Открыть с помощью Google Таблиц» → «Файл → Сохранить как Google Таблицу».
2. «Файл → Поделиться → Все, у кого есть ссылка → Читатель».
3. В приложении: кнопка «Данные» → поле «Google Таблица с ценами» → вставьте ссылку → «Подключить».
   Или откройте приложение по адресу `…/?sheet=<ID таблицы>` — ссылка запомнится на этом устройстве.
4. Изменили цену в таблице — нажмите «Обновить» (или перезагрузите страницу через 5 минут: кэш обновится сам).

Если лист «Категории», «Объекты» или «Позиции объектов» в таблице отсутствует, используется встроенная версия, а во вкладке «Данные» появится подсказка.

## Листы конструктора

| Лист | Что задаёт | Обязательные колонки |
|---|---|---|
| Категории | Разделы левого меню «Конструктор ремонта» | `category_id, name` (+ `icon, order, description, active`) |
| Объекты | Типы объектов: дверь, окно, отделка стен… | `type_id, category_id, name, renderer, placement, primary_slot` (+ `icon, description, lesson_steps, mistakes, active`) |
| Позиции объектов | Из чего состоит объект и как считается количество | `type_id, slot, label, qty, per` (+ `waste, optional, default_product_id, work_id, work_per, order`) |

* `renderer` — как рисовать в 3D: `door`, `entrance`, `window`, `wall`, `none`. Новые модели и цвета берутся из `attrs` товара (`style`, `color`, `handle`, `finish`).
* `placement` — к каким местам планировки относится тип: `door`, `entrance`, `window`, `room_walls`. Объекты создаются из проёмов и помещений автоматически.
* `per` — база количества: `pcs` (на объект), `opening_m2`, `opening_w`, `opening_h`, `opening_perimeter_m` (проём), `wall_m2` (стены без проёмов), `floor_m2`, `perimeter_m`, `ceiling_m2`.
* Товар может переопределить норму позиции через `attrs`: `rate=0.1;per=wall_m2;waste=0.15;work=W-WL-WP` — так обои считаются рулонами, а краска литрами в одной и той же позиции «Финишная отделка».
* Комплектации уровней (лист «Комплектации») для типов объектов: `academy` = `type_id` (например `door.interior`).

## Закрытая таблица через свой сервер

## 1. Создать таблицу

1. Откройте `docs/templates/3d-home-academy-catalog-template.xlsx` в Google Диске → «Открыть с помощью Google Таблиц» → «Файл → Сохранить как Google Таблицу».
2. Листы: **Товары, Цены, Работы, Комплектации, Поставщики, Расходники** (лист «Справка» система не читает). Названия листов и первую строку не менять.
3. Замените демо-числа своими ценами. `product_id` и `work_id` у существующих позиций не меняйте.

## 2. Доступ — таблица остаётся закрытой (рекомендуется)

1. Google Cloud Console → новый проект → включить **Google Sheets API** (бесплатно).
2. «IAM → Сервисные аккаунты» → создать аккаунт → вкладка «Ключи» → JSON-ключ. Файл хранить только на сервере.
3. В таблице «Настройки доступа» → добавить e-mail сервисного аккаунта с правом **«Читатель»**. Больше никому доступ давать не нужно.
4. ID таблицы — часть ссылки между `/d/` и `/edit`.

## 3. Настроить сервер

Скопируйте `.env.example` в `.env` (или задайте переменные в службе systemd / Docker):

```
GOOGLE_SHEETS_ID=1AbC...xyz
GOOGLE_SERVICE_ACCOUNT_FILE=/etc/3d-home-academy/service-account.json
CATALOG_TTL_SECONDS=300
```

Соберите фронтенд с источником «Google Таблица» и запустите сервер:

```bash
VITE_CATALOG_SOURCE=google-sheets npm run build
GOOGLE_SHEETS_ID=... GOOGLE_SERVICE_ACCOUNT_FILE=... npm start
```

Windows PowerShell:

```powershell
$env:VITE_CATALOG_SOURCE="google-sheets"; npm run build
$env:GOOGLE_SHEETS_ID="..."; $env:GOOGLE_SERVICE_ACCOUNT_FILE="C:\keys\sa.json"; npm start
```

Проверка: `http://localhost:8080/api/health` → `"catalog":"service-account"`, `http://localhost:8080/api/catalog` → листы.

## Как это работает

* Браузер обращается только к `/api/catalog` вашего сервера; ключи Google в браузер не попадают.
* Сервер кэширует листы (`CATALOG_TTL_SECONDS`), при сбое Google отдаёт последнюю копию с пометкой `stale`.
* Браузер тоже кэширует ответ; если сервер недоступен, а кэша нет — включается демо-каталог с предупреждением.
* При загрузке проверяются: обязательные колонки, единицы (`m2, m, pcs, set, kg, l, pack`), дубли идентификаторов,
  пустые цены, закупочная выше продажной, ссылки комплектаций. Замечания видны во вкладке «Данные».
* Позиция без цены не попадает в итог сметы и отмечается предупреждением — система не подставляет цены сама.
* Заказ хранит цены на момент оформления: изменение таблицы не меняет оформленные заказы.
* Принудительное обновление кэша: `GET /api/catalog?refresh=1` с заголовком `X-Admin-Token` (если задан `ADMIN_TOKEN`).

## Альтернатива — API-ключ

`GOOGLE_API_KEY` вместо сервисного аккаунта работает только для таблицы с доступом «всем, у кого есть ссылка».
Для закупочных цен этот вариант не подходит.
